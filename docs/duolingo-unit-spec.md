# Lexi 单元课程规范 v5

## 1. 数据链路与权威数据源

课程数据的源头是爬虫：`scripts/fetch-duolingo.mjs` 从 duome.eu 抓取各单元的 id / name / desc / words，加上 `file` 文件名映射后形成 `public/data/duolingo-zs-en.json`（运行时索引，已提交入库）。每个单元的讲义 Markdown 依据该索引生成，`<quiz-word-list>` 词表必须与索引的 `words` 数组逐字一致（顺序、大小写、短语内空格）。

`scripts/course-tools.mjs` 只做一致性反推，不改变数据源头方向：validate / build 扫描全部 Markdown 反推出索引，与现有索引比对——讲义与索引出现偏差时报错（validate）或重建（build）。索引不允许手工编辑。

每个索引项固定包含：

```json
{
  "id": 1,
  "name": "喜好",
  "desc": "使用基础词汇谈论喜好",
  "words": ["Chinese", "English"],
  "file": "001-喜好.md"
}
```

文件名、H1 编号和名称必须一致。Windows 文件名不支持的标点可从文件名中移除，但 H1 保留自然标题。

## 2. 文档结构

```markdown
# Unit 001: 喜好

> 使用基础词汇谈论喜好

## 单词

<quiz-word-list>

Chinese, English, book

</quiz-word-list>

## 单元讲解

普通 Markdown 讲解。

## Tips

- 词语提示。

## 练习

七种练习标签，顺序见下一节。
```

简介引用行（`> ` 开头）必须紧跟 H1 标题之后，内容与索引中的 `desc` 完全一致。注意：校验器用首个 `^> ` 行识别简介，若缺失会误把 Cloze 解析行当作简介，因此简介行绝不能省略。

所有自定义标签的开标签之后、闭标签之前必须各有一个空行。标签内容使用标准 Markdown，保证在普通 Markdown 阅读器中仍可阅读。

## 3. 固定七关

每个单元必须各有且只有一个以下标签，并保持源码顺序：

1. `<quiz-pronunciation-match>`：空标签，读取共享词表生成发音配对。
2. `<quiz-pronunciation-spell>`：空标签，读取共享词表生成发音填写。
3. `<quiz-translation-choice>`：空标签，读取共享词表与本地 ECDICT 生成中文选词。
4. `<quiz-sentence-builder>`：二十个带编号的中英文句对，每题配有深度语法与句法解析。
5. `<quiz-listening>`：恰好二十道同一主题微场景的听音辨句。
6. `<quiz-matching>`：显式表格至少十五组配对。
7. `<quiz-cloze>`：二十道一空三选项的填空题，每题只有一个正确项。

空标签仍必须保留标签内空行：

```markdown
<quiz-pronunciation-match>

</quiz-pronunciation-match>
```

## 4. 句库规则

- Listening、Sentence Builder、Cloze 三关的句库相互独立，各 20 题，不要求互相复用；三关围绕同一单元主题展开。
- Listening 固定二十句，每句都必须有自然中文翻译；英文不得重复，且必须覆盖至少 10 个不同的本单元词条或短语。
- Sentence Builder 与 Cloze 的英文句子同样不得重复，并应尽量覆盖本单元词条。
- 优先改编单元讲解和 Tips 中已有的可靠例句。
- 允许基础功能词、合理词形变化和支持场景衔接的常用表达；避免无关高级词汇。
- Cloze 逐题挖空本单元词条或短语，补全后必须是语法与语义完整的英语句子。
- Cloze 固定三个同类选项，只有一个答案在语法和语义上成立。
- 前端练习时每关从各自的 20 题库中随机抽取 10 题呈现，提供高复用性与练习多样性。

## 5. 标签格式

### 连词成句

```markdown
<quiz-sentence-builder>

1. **中文**：我喜欢我的书。  
   **英文**：I like my book.
   > **解析**：**like** 是及物动词，后直接接宾语，不需要介词；my 是第一人称单数物主代词，修饰名词 book。

</quiz-sentence-builder>
```

### 听音辨句

```markdown
<quiz-listening>

1. I like my book.
   > **中文**：我喜欢我的书。
2. You like your cat.
   > **中文**：你喜欢你的猫。

</quiz-listening>
```

实际文档必须正好二十题（与全量基线 290 单元 × 20 = 5,800 道听写一致）。

### 词义消消乐

空标签使用共享词表；显式模式使用两列表格，至少 15 组配对：

```markdown
<quiz-matching>

| 英文单词 | 课文释义 |
| --- | --- |
| book | 书本 |

</quiz-matching>
```

显式表格必须与本单元词表一一对应：覆盖全部词表词条、不得包含词表以外的词（如 I、is、the 等练习句中的功能词不允许出现），释义使用中文。表格至少 15 组配对。

### 选词填空

```markdown
<quiz-cloze>

### 1

I ____ my book.

- [x] like
- [ ] likes
- [ ] liking

> **解析**：主语 I 后使用动词原形。

</quiz-cloze>
```

固定二十题，编号从 `### 1` 到 `### 20`；每题正好一个 `____` 空位、三个同类选项、一个正确项，补全后必须是完整通顺的英语句子。

## 6. 生成风格要求

重新生成单元内容时，除结构校验外还须满足以下质量要求（参考 001、002 单元的既有风格）：

### 单元讲解

- 二至三段普通 Markdown，不使用列表。
- 第一段点明主题，把词表按语义分组（如"身份词 + 动词 + 名词"），并给出能拼出的典型句子。
- 指出本单元的语法主线（如 be 动词搭配、第三人称单数、物主代词扩展），并说明与前面单元的衔接。
- 末句说明"学完能做什么"。

### Tips

- 条数随词表规模弹性调整（词表 15–35 词，建议 8–12 条）；Tips 连同单元讲解必须覆盖词表全部词条，并可补充词表之外但对句型关键的语法词（如 be 动词）。
- 每条覆盖一个词或一组相关词，格式为 `- **词** — 讲解`；相关词合并成组讲解（如 father/mother、同类颜色词），避免逐词流水账。
- 每条至少包含用法与例句；适用时补充常见错误对照（✗/✓）、习惯表达、词源或构词分析。
- 优先讲解词表中的语法功能词（代词、动词、连词），它们决定句型；实义名词按语义分组后置。

### 练习内容

- 三关句库相互独立，各自围绕单元主题组织 20 句，只使用本单元词条、基础功能词、合理词形变化及支持场景衔接的常用表达。
- Sentence Builder 每题解析必须给出语法依据（主谓一致、句子成分、词性要求等），不写空泛结论。
- Cloze 的干扰项须与正确答案同类（同为颜色词、同为代词等），保证语法或语义上只有唯一正确答案；解析说明排除理由。
- Matching 释义使用中文，词条顺序与词表一致，补充的功能词放在单元词条之后。

## 7. 内容边界

- 词表迁移保留原有顺序和大小写；大小写不同但语义重复的历史项只保留首次出现者。
- 讲解和 Tips 可以继续使用普通 Markdown，不应包含未登记的 `<quiz-*>` 标签。
- 中文翻译和解析静态写入 Markdown，运行时不调用 AI 或在线翻译。
- 课程内容不声称是第三方课程的官方教案；不确定的语法目标使用“可以练习”等审慎表述。

## 8. 构建与自检

```bash
npm run validate:course
npm run build:course
npm run build
```

- `validate:course` 只读校验全部 290 个 Markdown 和当前索引。
- `build:course` 校验后重新生成公开索引。
- `build` 先执行课程校验，再执行 Vite 生产构建。
- 任何未知/重复标签、空行错误、词表重复、二十题数量错误、中文缺失、句子重复或编号不一致都会使构建失败，并报告文件及行号。
- 全量基线为 290 个单元、2,030 个关卡、5,800 道 Listening 和 7,611 个有效词条。

`scripts/fetch-duolingo.mjs` 的抓取结果只写入 `data/`，仅作导入参考，不能覆盖公开索引。
