# 多模型多邻国讲义编写规范

## 数据与独立编写

`public/data/duolingo-zs-en.json` 是单元编号、名称、描述、目标词表和文件名的唯一来源。保留其内容和顺序；不要从讲义反向生成或覆盖它。

为一个模型编写新讲义时，只读取该原始 JSON、本文和当前任务要求。不得读取、复制、改写或参考 `public/data/duolingo-zs-en/` 的旧正文，也不得参考其他模型版本的正文。旧版本仅用于页面展示和机械兼容性校验，校验输出不得包含旧讲义正文。

## 目录与文件

- 版本目录为 `public/data/duolingo-zs-en.<version-id>/`，例如 `duolingo-zs-en.gpt-6.1/`。
- 讲解文件严格使用原始 JSON 的 `file`，例如 `001-喜好.md`。
- 练习使用同名的 `001-喜好.test.md`，遵循 [独立练习规范](duolingo-practice-spec.md)；它不进入讲义清单。讲解与练习可分别逐课发布。
- 各版本可以逐课发布，不要求一次完成全部单元。缺失的课显示待编写，不引用其他版本补齐。

## 讲解原则

面向中文母语初学者，采用循序渐进的小册子风格。每课包含学习目标、自然场景、核心表达、词语关系、原创例句和易错点；结构可随主题调整，不用机械模板堆砌内容。

用普通 Markdown，一级标题与原始单元名称一致。讲解里不放习题、答案、练习标签或重复定义词表的 `<quiz-word-list>`。可以引用目标词和例句；必要的辅助词及词形变化需简短解释，不更改目标词表，不为覆盖词汇编造生硬语境。

## 注册与校验

在 `public/data/duolingo-zs-en.versions.json` 的 `versions` 中新增 `{ id, label, directory, format: "split", guideUnitIds: [] }`。ID 使用小写字母、数字、点或连字符，目录与 ID 对应。清单中的 `defaultVersionId` 指定首次使用的默认版本。

运行 `npm run build:course`，分别更新讲义的 `guideUnitIds` 和独立练习的 `practiceUnitIds`；运行 `npm run validate:course` 验证原始数据、原版兼容性、新版文件与清单。两个命令都不修改原始 JSON 或旧讲义。练习文件会进行独立格式校验，不要求固定题型或题量。

新版词汇始终来自原始 JSON。网页保存版本偏好与浏览位置；旧关卡进度只属于原版。新版练习进度按模型与单元隔离。添加内容后检查桌面和手机的版本选择、缺课提示和练习流程。
