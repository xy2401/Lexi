# Lexi 系统课程编写与排版设计规范 (System Course Specification)

> **版本**：1.0  
> **适用范围**：`public/data/system-courses/*.md` 及课程体系规划  
> **核心宗旨**：**扎实教学、客观沉稳、结构清晰、极简纯粹、充分发挥 Markdown/HTML/Mermaid 原生排版威力。**

---

## 一、 教学理念与语言文风规范

### 1. 拒绝营销煽动，回归纯粹讲课
- ❌ **严禁词汇与噱头**：严禁出现“全攻略”、“终极杀手锏”、“金牌法则”、“双剑合璧”、“黄金词根”、“20大/4大”等博人眼球的营销号词汇或数字噱头；**严禁在标题中出现“英语”等冗余字眼**（如“计算机网络英语”必须简化为“计算机网络与云原生架构”）。
- ✅ **推荐文风与标题**：极致朴实、平实精练、沉稳直接的专业教学语言（如《核心词根与词缀》、《动词时态体系》）。
- 💡 **技巧认知**：所有谐音、记忆口诀、技巧**仅作为辅助理解的工具**，必须在导读和正文中客观说明，不夸大、不神化技巧，实事求是。

### 2. 教学动线：先总览全景，再深入细节
- **先见森林，后见树木**：每一门系统课第一章必须先给出**顶层全景架构图/分类总览**（例如 48 个音标全貌分类、时态全景坐标轴等），让读者一开始就能看清整体知识地图。
- **层层递进**：
  1. 顶层全景分类与架构图；
  2. 核心原理与底层拼读/构词机制；
  3. 核心规则对比与实战解析；
  4. 分类逐项精讲与唇齿/发音/用法拆解；
  5. 本课核心练习词汇（纯粹沉浸式自练）。

## 二、 排版与格式技术规范

### 1. 彻底杜绝 ASCII 字符画
- ❌ **严禁**使用黑底代码框（`pre/code`）手绘字符画（如 `┌── ... ──┘`、`├──`、字符箭头等）。
- ✅ **正确方式**：
  - 结构关系/知识树/流程脉络：统一使用 **Mermaid.js** 绘制原生矢量导图；
  - 规则对比/分类数据：统一使用 **Markdown 标准表格（Table）**；
  - 提示与口诀：统一使用 **引用提示卡片（Blockquote）**；
  - 步骤流程：使用 **有序列表或行内文字箭头（→）**。

### 2. Mermaid 图表语法场景适配选型规范
根据不同的知识领域与认知模型，选择最具表达力的专用 Diagram 语法：

| 知识场景 | 最适配 Diagram 类型 | 语法标识符 | 核心表达威力 | 典型应用课程 |
| :--- | :--- | :--- | :--- | :--- |
| **版本控制 / 分支演化** | **Git Graph** | `gitGraph` | 原生呈现分支拉取、提交、变基、合并与 Cherry-pick | `Lesson 11: 开发与工程常用术语` |
| **网络协议 / 交互时序** | **Sequence Diagram** | `sequenceDiagram` | 呈现客户端、DNS、网关、数据库之间的顺序通信流 | `Lesson 12: 计算机网络与云原生架构` |
| **语法状态演化 / 动作转换**| **State Diagram** | `stateDiagram-v2` | 呈现非谓语动词从意图、执行到终态的生命周期 | `Lesson 06: 非谓语动词` |
| **时态坐标 / 历史演进** | **Timeline** | `timeline` | 呈现时态在过去、现在、将来的时间锚点演进 | `Lesson 04: 动词时态体系` |
| **构词装配 / 架构模型** | **Class Diagram** | `classDiagram` | 呈现前缀+词根+后缀的面向对象组装关系 | `Lesson 08: 核心词根与词缀` |
| **技术层级 / 分类知识树**| **Flowchart / Graph** | `graph LR / TB` | 呈现包含关系清晰的层级树与全景地图 | `Lesson 01 音标 / 10 AI大模型` |

### 3. HTML 行内精细高亮规范
为了在表格和正文中突出特殊形式与词缀变异，充分利用已内置的专属 HTML/CSS 样式：

| 变化类别 | 专属标签与类名 | 视觉效果 | 适用场景 | 示例 |
| :--- | :--- | :--- | :--- | :--- |
| **特殊形式** | `<code class="ord-special">...</code>` | 珊瑚红柔和底色 + 红色加粗 | 完全不规则的独立词汇 | `<code class="ord-special">first</code>` |
| **变异形式** | `<code class="ord-variant">...</code>` | 琥珀橙黄底色 + 橙色加粗 | 词根/词缀发生拼写变异 | `<code class="ord-variant">fifth</code>` |
| **常规形式** | <code>\`...\`</code> | 标准清爽浅蓝底色 + 等宽字体 | 规律变化的普通单词/词组 | `fourth`, `tenth` |

> [!IMPORTANT]
> - 变异单词必须作为一个完整的 `<code>` 实体包裹（如 `<code class="ord-variant">twelfth</code>`），确保用户点击时能稳定识别并朗读完整单词。

## 三、 表格设计与列宽自适应规范

### 1. 精炼列结构，杜绝冗余
- 避免拆出过多无意义的空泛列（如“变化类型”大列），应将信息紧凑合并；
- 表格行竖线必须严格对应列数，严禁多加或漏写 `|`。

### 2. 列宽与换行法则
- **第 1 列（标签/规则/序号/基数词）**：保持紧凑（`width: 1%; white-space: nowrap;`），不可折行；
- **内容说明列（规律解释、例句、发音技巧）**：允许自适应自然换行（`white-space: normal; word-break: break-word;`），杜绝强加 `nowrap` 导致挤压变形；
- 表格第一列文字根据 Markdown 语义自然呈现，不强行全局粗体。

## 四、 单词可点击性与 TTS 发音规范

1. **单词规范包裹**：
   - 讲义中所有涉及发音、查词的英文单词、数字全拼、缩写均需用行内反引号包裹（如 `one`, `1st`, `cake`, `think`）。
2. **职责分工明确（非音标课不堆砌音标与孤立释义）**：
   - 只有 Lesson 01（音标课）与 Lesson 03（语流音变课）专注音素发音动作时标注音标；
   - 其余非发音类课程（如语法、词根、科技与工程课）**严禁在表格中设立机械的「音标列」或单字字典释义列**。讲义专注于知识脉络、逻辑关系与工程原理解析，音标展示与生词查阅全权交由点击单词后弹出的 **Lexi 词典 Card** 处理。
3. **代码块视觉独立性 (No Wrap)**：
   - 所有的 `code` 标签在 CSS 中均配置为 `white-space: nowrap; display: inline-block;`，确保单词、长短语或音标作为一个整体不可分割，绝不在行末发生折断。
4. **移除冗余组件**：
   - 页面顶部不设置重复冗余的“核心词汇快捷条”，讲义底部保留章节「核心练习词汇」，保持沉浸式纯粹阅读。

## 五、 课程文件与目录配置规范

### 1. 清单文件：`public/data/system-courses.json`
每个课程项包含以下字段：
```json
{
  "id": 1,
  "slug": "phonetics-mastery",
  "title": "国际音标与自然拼读",
  "desc": "48 个音标分类、音素拼读合成与自然拼读规则。",
  "tag": "发音与拼读",
  "icon": "🗣️",
  "file": "/data/system-courses/01-phonetics-mastery.md",
  "words": [
    "cake", "bike", "rose", "cute", "rain", "boat", "house", "cheese", "milk", "apple"
  ]
}
```

### 2. 讲义文件命名与存放：`public/data/system-courses/`
- 命名格式：`01-xxx.md`、`02-xxx.md`、`03-xxx.md`；
- 标题规范：
  - `# 一级标题`：课程总标题（必须与 JSON 标题一致，朴实精简，自动在页面顶栏呈现）；
  - `## 二级标题`：主要大章（自动生成右侧目录大纲一级项，平滑滚动与高亮同步）；
  - `### 三级标题`：小节细目（自动生成右侧目录大纲二级缩进项）。

## 六、 课程编写检查清单（Checklist）

每次新增或修改课程讲义前，对照本清单自检：

- [ ] **标题与文风**：标题和描述是否极致朴实简短？是否清除了“黄金/20大/四大/全攻略/英语”等冗余词汇？
- [ ] **职责清晰**：除音标专项课外，表格中是否清除了多余的“音标列”，将生词查阅全权交给了 Lexi 词典 Card？
- [ ] **全景先行**：第一章是否提供了与知识场景最适配的顶层 Mermaid 图表（如 `gitGraph`, `sequenceDiagram`, `timeline`）？
- [ ] **无字符画**：是否完全没有使用 ASCII 符号拼接的方框或代码块？
- [ ] **高亮得当**：特殊词汇/变异词缀是否正确使用了 `<code class="ord-special">` / `<code class="ord-variant">`？
- [ ] **表格对齐**：表格列数是否精炼？竖线分隔是否一一对应？列宽是否自适应自然换行？
- [ ] **发音测试**：表格与正文中的每个单字、短语（如 `a third`）点击后是否都能稳定清晰朗读？
- [ ] **目录联动**：右侧大纲目录（TOC）是否能正常显示各级标题，点击能否平滑直达对应章节？
