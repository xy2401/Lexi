# Lexi 系统课程编写规范

> **版本**：3.3<br>
> **适用范围**：`public/data/system-courses/[0-9][0-9]-*.md`、课程清单及相关课程界面<br>
> **配套文档**：课程分类、主题边界、纵向深度和长期目录见 [`_curriculum.md`](./_curriculum.md)。<br>
> **内容原则**：准确、朴实、循序渐进；默认像专业小册子一样安静易读，需要时再提供 Web 交互。

---

## 一、文档职责与适用边界

### 1. 文件职责

- `_curriculum.md`：课程体系、分类、主题边界、纵向深度、推荐路径和长期目录；
- `_spec.md`：课程与章节的写作、排版、语义标签、交互和验收规范；
- `system-courses.json`：当前已经发布并在界面展示的课程清单；
- `[0-9][0-9]-*.md`：当前实现使用的课程正文。

`_*.md` 是内部规划或规范文件，不进入课程列表，也不按课程正文模板校验。

### 2. 课程与词典的职责分工

系统课程负责解释英语形式、领域术语之间的关系和真实用法；Lexi 词典 Card 负责完整单词的释义、音标、词性和朗读。

- 发音课程可以集中标注音标和发音动作；
- 其他课程不设置机械的“音标列”或逐词释义列；
- 正文只解释与当前概念直接相关的词义差别；
- 词根、前缀、后缀等非完整单词只展示结构，不发起词典查询；
- 生词数量不能代替内容质量；术语必须通过概念关系、搭配和真实语境组织，不能只堆成清单。

### 3. 英语课程与领域知识的边界

Lexi 是英语课程，不是计算机、人工智能、科研、化学或其他专业方向的入门教材。

- 语言系统课程可以深入讲解发音、词汇、语法、语义和篇章，因为这些就是英语本身；
- 领域英语课程帮助读者快速识别该领域的英文术语、缩写、常见搭配、句型和文档表达；
- 领域概念只解释到足以区分术语、读懂上下文的程度；
- 不教授如何训练模型、设计网络、管理集群、开展实验或解决该领域的专业问题；
- 不用学科推导、操作流程或专业问题集制造虚假的“课程深度”；
- 如果一段内容删掉英文术语后仍是一段完整的学科教程，它通常已经超出课程边界。

领域英语课程优先回答：

1. 这个术语在英文材料中通常指什么；
2. 它与相邻术语有什么区别；
3. 常与哪些动词、形容词或名词搭配；
4. 在文档、论文、界面或报错中如何出现；
5. 哪些中文直译容易造成误解。

### 4. 发音基准

Lexi 当前 TTS 使用 `en-US`，课程以通用美式发音为主要示范。涉及其他常见读音时，应明确标注变体，不把口音差异写成正误差异。

音素数量会因口音和分析方法不同而变化。课程可以介绍传统音标表，但不能把某个固定数量描述为所有口音唯一正确的体系。

## 二、课程与章节编写结构

### 1. 课程导读

每门课程围绕一个中心问题展开。课程导读必须包含：

1. 中心问题；
2. 适用读者与阅读场景；
3. 术语或语言关系地图；
4. 本课包含和暂不包含的内容；
5. 推荐的快速阅读路径。

课程主题和章节深度以 `_curriculum.md` 为准，不在正文中另建相互冲突的课程分类。

### 2. 单章必备组成

每个章节解决一个可以清楚陈述的语言问题。下列组成可以按内容合并：

1. **问题语境**：说明术语或语言形式会在什么材料中出现；
2. **核心解释**：用最少的领域知识解释其基本概念；
3. **术语关系**：比较容易混淆的词、缩写或表达；
4. **搭配与例句**：展示真实英文搭配、完整句子和文档片段；
5. **边界和例外**：说明直译、语域、变体和概念边界；
6. **快速回看**：汇总读者再次遇到这些表达时应注意什么。

### 3. 推荐章节骨架

```markdown
# 课程标题

> 中心问题：……<br>
> 核心成果：……<br>
> 阅读建议：……

## 一、课程导读与知识地图

## 二、直觉入门

## 三、核心模型

## 四、系统规则与对比

## 五、边界与例外

## 六、真实材料中的表达

## 七、常见误读与边界

## 八、术语回看与参考
```

当前单文件课程可以使用这一骨架。领域英语课程应保持可快速浏览，不为追求篇幅填入专业训练内容。

### 3.1 中长篇与反模板要求

- 发布课程默认是中长篇连续阅读材料；一个主题应优先在同一门课中完成「概念 → 对比 → 搭配/例句 → 边界」的叙述；
- 每门发布课程必须有中心问题、课程边界和至少六个实质主题段；主题段不能只由术语列表、表格或换名例句构成；
- 不把词义、搭配、短语、同义词，或研究方法、测量、统计等天然相连的内容拆成同模板的小课；
- 每门课必须有该主题特有的论述、对比与例子。只替换术语、标题或示例名词的内容不能发布；
- 单词课程尤其要提供词义边界、词族、搭配、语域和可复用句框，不能以双语词表代替讲解；
- 时间、空间、数字等概念词汇课程应说明其与时态、介词等语法课程的边界，避免为了独立成课而重复规则；
- 需要减少单元数量时，先合并共享阅读任务和同一核心模型的内容，而不是删掉解释；
- 课程的深度由关系是否讲清、材料是否可读决定；不以空泛模块、表格数量、练习或术语数量制造篇幅。

### 4. 讲解顺序

每个重要知识点按以下顺序展开：

1. 给出真实、简短的语境；
2. 指出需要观察的形式或关系；
3. 解释判断模型；
4. 比较相近形式；
5. 说明适用边界和常见例外；
6. 给出真实搭配、例句或文档片段；
7. 用简短回看结束，不附题目和答案。

不能先罗列整页术语，再依靠学习者自行建立联系。

### 5. 深度处理

- 入门内容使用直观语言，但不能用错误规则换取简单；
- 核心模型必须足以支持后续章节迁移；
- 语言系统课程的深层章节可以引入语言学术语、历史背景、理论争议和研究视角；
- 领域英语课程的深度来自术语关系、语域、搭配和真实材料，不来自学科难度；
- 深层内容必须指出它如何扩展或修正前面的模型；
- 不把篇幅、术语数量或复杂例句数量当作深度；
- 不要求学习者读完学术延伸，才能进入其他课程的核心章节。

### 6. 不设置课后练习与答案区

- 课程正文不设置“练习”“综合任务”“查看答案”或“答案与分析”章节；
- 不要求读者完成学科问题、配置任务、推导或测验；
- 必要的语言对比直接在讲解处给出结论和原因，不把解释折叠到答案区；
- 发音、朗读和查词通过正文中的 Web 交互自然发生，不另设作业；
- 课程结尾使用“本课回看”“术语速览”或“延伸资料”，帮助快速复查。

### 7. 累积复现

- 新例句应有意识地复用前面章节的词汇和模型；
- 相同规则只在最合适的章节完整解释一次；
- 后续出现前置知识时使用链接或简短提醒，不完整复制旧内容；
- 领域课程重复出现核心搭配时，可以链接到词典或前文，不复制完整定义。

## 三、内容与语言规范

### 1. 标题与文风

- 标题直接说明知识对象，不加入“全攻略”“杀手锏”“黄金法则”“超级”“三剑客”等宣传性措辞；
- 不用“几大”“必学多少个”等数字制造重要感；数量只有在表达客观分类时使用；
- 不在标题中重复无助于辨识主题的“英语”二字；
- 使用简洁、克制的教学语言，不用训诫、夸张承诺或拟人化包装代替解释；
- 口诀、谐音和记忆技巧只能作为辅助，并说明适用范围；
- 首次使用必要术语时给出中文解释，之后保持命名一致。

### 2. 准确性

- 区分教学模型与语言事实，不把便于入门的模型称为唯一规则；
- 说明规则适用范围，并给出足以影响判断的常见例外；
- 时态课程可以使用“时间 × 状态”模型，但不把传统形式数量当作学习目标；
- 构词课程不能根据字形随意拆词，词源不确定时不得写成事实；
- 技术课程优先解释稳定概念；涉及版本、产品行为或现行标准时查验官方资料；
- 示例必须符合真实表达习惯，不为迁就规则编造生硬句子。

### 3. 示例设计

- 一个示例尽量只引入一个主要难点；
- 规则对比尽量保持语境、主语和核心词一致；
- 从短句过渡到完整上下文，不全程使用孤立短语；
- 中文解释表达自然含义，不使用逐词硬译伪造对应关系；
- 技术示例接近真实界面、命令、日志或文档，但不包含密钥、真实账号和危险命令；
- 学术示例先解释问题，再引入术语和分析方法。

### 4. 内容边界

- 章节开头明确本章讲什么和暂不讲什么；
- 跨课程知识使用链接或前置提示，不在一章中无限扩展；
- 技术课程围绕工作流、系统链路或生命周期组织，不退化为术语百科；
- 附录承担集中查阅功能，不用大表格打断核心教学主线。

## 四、Markdown 与版式规范

### 1. 标题层级

- `#`：课程总标题，必须与课程清单中的 `title` 一致；
- `##`：主要章节，进入右侧目录一级项；
- `###`：章节内小节，进入右侧目录二级项；
- 不跳级使用标题，不用粗体段落模拟标题；
- 标题应能单独说明内容，避免连续使用“其他”“补充”“更多”等模糊名称。

### 2. 信息表达方式

| 信息关系 | 首选形式 |
| :--- | :--- |
| 顺序和步骤 | 有序列表 |
| 分类及较长说明 | 无序列表 |
| 相同维度横向比较 | Markdown 表格 |
| 层级、流程和状态转换 | Mermaid 图 |
| 补充、警告和适用边界 | Blockquote 提示卡片 |
| 实际代码、命令和日志 | fenced code block |
| 单词、短语和例句交互 | 行内代码；渲染器自动识别单词或短语／句子 |
| 词根词缀结构 | `lexi-morpheme` |
| 音标与音素符号 | `lexi-phoneme` |
| 公式、变量与分析记号 | `lexi-notation` |

禁止使用代码块绘制 ASCII 方框、树形图或字符箭头。简单关系用一句话可以说清时，不为了装饰强行加入图表。

### 3. Mermaid 图表

根据知识关系选择图表：

| 知识关系 | 建议类型 | 常见场景 |
| :--- | :--- | :--- |
| 层级与处理流程 | `flowchart` | 句子扩展、技术架构、构词流程 |
| 交互顺序 | `sequenceDiagram` | DNS、HTTP、网关和服务调用 |
| 状态变化 | `stateDiagram-v2` | 动作、任务或连接生命周期 |
| 时间演进 | `timeline` | 时间锚点或技术发展脉络 |
| 版本分支 | `gitGraph` | Git 分支、合并与变基 |
| 结构成员关系 | `classDiagram` | 构词结构或系统实体关系 |

图表要求：

- 图前说明阅读目的，图后解释关键关系；
- 节点文字简短，详细解释放在正文；
- 不依靠颜色单独传达意义；
- 在桌面端、移动端和全屏查看中验证；
- 无法稳定渲染时改用表格或列表，不保留损坏占位。

### 4. 表格与列表

选择表格前先回答：去掉列对齐后，信息是否明显更难比较？只有答案为“是”时才使用表格。

表格不是默认的信息容器，也不用于制造“内容很系统”的视觉效果。课程正文应先建立连续讲解，再在确有比较任务的位置插入少量表格；不能把一章拆成连续的资料表。

适合表格：

- 多组对象需要沿相同维度比较；
- 原形、变化形式、缩写或功能需要逐行对齐；
- 单元格内容简短，列之间具有稳定关系。

适合列表：

- 规则分类及其例子；
- 有先后顺序的操作或判断过程；
- 每项包含较长解释、完整句子或补充条件；
- 去掉列线后仍然可以自然阅读。

优先替代表格的 Web 表达：

- 最小对立、词形和例词：使用可点击朗读的成对条目或对比卡；
- 术语及其解释：使用定义条目、短段落或可展开补充；
- 发音部位、层级和空间关系：使用图解配编号列表；
- 少量并列概念：使用分组列表或并列概念块；
- 方向、过程和状态变化：使用 Mermaid、箭头关系或步骤列表。

表格要求：

- 常规表格控制在 2—4 列；超过 4 列时优先拆表、分组或改用列表；
- 第一列不全局强制 `nowrap`；
- 单词可以保持不换行，句子和说明文字必须自然换行；
- 不重复已经在表格前统一说明的规则；
- 不拆出内容高度重叠的列；
- 不在单元格中放置长句、长段解析或多层列表；
- 表头和每一行的竖线数量一致；
- 窄屏优先拆分内容，横向滚动只是最后的兼容措施。
- 同一章节出现两张以上表格时必须重新审查：能否合并为一张真正的比较表，或将其中一张改为列表或图解；
- 完稿后逐表执行“去掉列线测试”，删除不依赖列对齐仍能自然阅读的表格。

### 5. 专业小册子与 Web 能力

默认阅读体验应像一本安静、专业、可以连续阅读的小册子：章节稳定、留白充分、颜色克制、概念层次清楚，不使用无意义动画和持续抢占注意力的组件。

优先发挥的 Web 能力：

- 单词按需查词和朗读；
- 句子按需朗读并显示播放状态；
- 边界情况和非核心补充材料可以使用可展开区域逐步披露；
- Mermaid 图表支持放大；
- 标题锚点、目录定位和阅读进度联动；
- 表格、列表和图表响应屏幕宽度；
- 所有核心交互支持键盘和清晰焦点状态。

## 五、语义标签与视觉规范

### 1. 基本模型

课程标记采用两个独立维度：

- **内容类型**决定点击行为：单词、句子、词素；
- **形式状态**决定视觉样式：普通、规则变化、变体、不规则。

形式状态不能改变内容类型的交互。不规则单词仍然可以查询词典，不规则词根仍然不能查询词典。

### 2. 作者语法

| 内容类型 | Markdown 写法 | 点击行为 |
| :--- | :--- | :--- |
| 普通单词 | 行内代码，如 `build` | 立即朗读并打开词典 Card |
| 短语或句子 | 行内代码，如 `The project builds successfully.` | 只朗读，不查询词典 |
| 规则变化单词 | `<lexi-word form="changed">` 包裹一个行内代码 | 朗读并打开词典 Card |
| 不规则单词 | `<lexi-word form="irregular">` 包裹一个行内代码 | 朗读并打开词典 Card |
| 词根或词缀 | `<lexi-morpheme>` 包裹一个行内代码 | 不朗读，不查询词典 |
| 变体或不规则词素 | `<lexi-morpheme form="variant">` 或 `form="irregular"` | 不朗读，不查询词典 |
| 音标或音素符号 | `<lexi-phoneme>` 包裹一个行内代码 | 不调用 TTS，不查询词典 |
| 公式、变量或单个结构槽位 | `<lexi-notation>` 包裹一个行内代码 | 不朗读，不查询词典 |

```markdown
普通单词：`build`

句子：`The project builds successfully.`

规则变化：`four` → <lexi-word form="changed">`fourth`</lexi-word>

不规则单词：`one` → <lexi-word form="irregular">`first`</lexi-word>

词根：<lexi-morpheme kind="root">`spect`</lexi-morpheme>

前缀：<lexi-morpheme kind="prefix">`in-`</lexi-morpheme>

前缀变体：<lexi-morpheme kind="prefix" form="variant">`im-`</lexi-morpheme>

后缀：<lexi-morpheme kind="suffix">`-ion`</lexi-morpheme>

音素：<lexi-phoneme>`/ɪ/`</lexi-phoneme>

公式：<lexi-notation>`F0 = 1 / T`</lexi-notation>

结构槽位：<lexi-notation>`主语`</lexi-notation> + <lexi-notation>`助动词`</lexi-notation> + <lexi-notation>`谓语其余部分`</lexi-notation>

术语链：`client` → `server` → `response`
```

属性取值：

- `lexi-word.form`：`changed`、`irregular`；
- `lexi-morpheme.kind`：`prefix`、`root`、`suffix`；
- `lexi-morpheme.form`：`variant`、`irregular`；
- `lexi-sentence` 为旧内容兼容标签；新增内容不使用它；
- `lexi-phoneme` 不使用属性；
- `lexi-notation` 不使用属性；
- 新增普通单词不写 `<lexi-word>`；直接使用行内代码。省略 `form` 的旧标签仍兼容为普通形式；
- 自定义作者标签统一使用 `lexi-` 前缀和小写 kebab-case；
- 标签内部恰好包含一个行内代码片段，不跨段落、不嵌套、不包裹 fenced code block。

### 2.1 最小交互单位

标签只包裹能够独立承担其行为的最小单位，不能为了排版把一条关系、一个顺序或一个构词过程整体高亮。

- 英文单词逐个使用普通行内代码，使每个词都能查词并朗读；`<lexi-word>` 只用于 `changed`、`irregular` 两种形式状态；
- 可完整朗读的短语或句子也直接使用行内代码；渲染器检测到空格后只提供朗读，不查询词典；
- 词根、词缀和其变体逐个使用 `<lexi-morpheme>`；
- 数字分节、语法槽位等不可查词的结构成分逐个使用 `<lexi-notation>`；
- `→`、`+`、`|`、`/`、`=`、括号和逗号是关系符号，保留为普通文本，不包进前后标签；
- 只有公式、变量关系等本身不可拆的记号，才允许一个 `<lexi-notation>` 包住完整表达式。

历史课程中若遗留 `` `decide / hope / plan` `` 这样的整段行内代码，渲染器会兼容地将其拆成逐词标签；新增内容仍必须在 Markdown 中明确写成 `` `decide` / `hope` / `plan` ``，让源文件本身也保持正确语义。

因此，不能写成 `<lexi-notation>`client → server → response`</lexi-notation>`，应写成 `` `client` → `server` → `response` ``；不能写成 `<lexi-notation>`in- + possible`</lexi-notation>`，应分别标记词素和单词。

### 3. 交互行为

- 单词点击后立即朗读，同时打开词典 Card；
- 句子允许自然换行，点击后只朗读；
- 词根、前缀、后缀、音素符号和分析记号不使用指针光标或按钮式悬停效果；
- 可点击内容支持键盘聚焦，并可使用 `Enter` 或空格触发；
- 朗读状态不能引起布局跳动；
- 实际命令、代码、配置和日志不参与课程词典交互。

### 4. 视觉样式

所有标签采用低饱和、低刺激的样式，不使用大面积纯色、强阴影、荧光色或警告式红色。

| 类型 | 视觉方向 |
| :--- | :--- |
| 普通单词 | 极浅冷灰蓝背景、克制的蓝灰文字、小圆角；悬停后才增强边框或底色 |
| 句子 | 接近正文，可自然换行；使用浅底色或细虚线提示可朗读，不使用厚重胶囊 |
| 规则变化 | 柔和灰绿色，表示由当前规则得到 |
| 不规则形式 | 柔和沙金色，不使用红色，避免被理解为错误 |
| 普通词根词缀 | 淡紫灰或中性灰轮廓，保持等宽字体，不呈现按钮感 |
| 变体词根词缀 | 在词素样式上增加沙金色细边框或轻微底色，不增加点击反馈 |
| 音标与音素符号 | 中性靛灰色、浅轮廓和等宽字体，不伪装成可由浏览器 TTS 准确朗读的内容 |
| 公式与分析记号 | 中性灰蓝色、等宽字体，保持结构完整但不呈现按钮感 |

视觉实现要求：

- 单词保持整体不换行，句子必须允许换行；
- 相邻标签之间保留稳定的小幅空白，不依赖作者手动输入多个空格，也不让背景和边框相互黏连；
- 同一形式状态在单词和词素上可以共享色调，但交互反馈必须不同；
- 可点击内容有悬停、键盘焦点和按下状态；不可点击词素没有这些反馈；
- 不规则形式不是错误，不使用错误图标、红色警告或删除线；
- 不只依靠颜色区分类型，还结合边框、形状、光标和上下文说明；
- 标签在正文、列表和表格中的字高、基线和行距保持稳定。

### 5. 规则说明与内容去重

规则集中解释一次，后续例子通过分组、顺序和形式样式表达归属，不在每一行重复同一句说明。

```markdown
多数序数词在基数词后加 `-th`：

- `four` → <lexi-word form="changed">`fourth`</lexi-word>
- `six` → <lexi-word form="changed">`sixth`</lexi-word>
- `ten` → <lexi-word form="changed">`tenth`</lexi-word>

以下形式需要整体记忆：

- `one` → <lexi-word form="irregular">`first`</lexi-word>
- `two` → <lexi-word form="irregular">`second`</lexi-word>
- `three` → <lexi-word form="irregular">`third`</lexi-word>
```

需要对齐缩写时，可以使用“基数词、序数词、缩写”三列表格，但不再增加逐行重复的“变化规则”列。

词根词缀先解释变体出现的环境，再列出变体和完整派生词。词素只承担结构展示，完整单词另用单词标记提供词典交互。

### 6. 迁移兼容

旧作者标签 `<lexi-irregular>`、`<lexi-variant>` 和 `<lexi-sentence>` 只在迁移期间保留。新内容只在需要特殊语义时使用 `lexi-word`、`lexi-morpheme` 等受控标签；完成课程迁移后删除旧标签支持。

## 六、课程文件与元数据

### 1. 当前文件规则

- 清单文件：`public/data/system-courses.json`；
- 正文目录：`public/data/system-courses/`；
- 规划与规范：`_curriculum.md`、`_spec.md`；
- 当前课程文件：`01-xxx.md`、`02-xxx.md`；
- `_*.md` 不进入课程列表；
- 编号、JSON 中的 `id`、显示顺序和文件名前缀在当前实现中保持一致；
- `slug` 使用稳定、朴实的英文描述。

### 2. 当前必需字段

```json
{
  "id": 3,
  "slug": "sentence-components-and-patterns",
  "title": "句子成分与基本句型",
  "desc": "句子主干、成分关系与常见基本句型。",
  "tag": "句子与语法",
  "icon": "🧱",
  "file": "/data/system-courses/03-sentence-components-and-patterns.md",
  "words": ["subject", "verb", "object", "complement"]
}
```

| 字段 | 要求 |
| :--- | :--- |
| `id` | 从 1 开始连续编号，并与当前显示顺序一致 |
| `slug` | 唯一、稳定，使用小写 kebab-case |
| `title` | 与 Markdown 一级标题完全一致 |
| `desc` | 一句话说明中心问题或核心成果，不使用宣传词 |
| `tag` | 使用 `_curriculum.md` 中定义的课程分类 |
| `icon` | 一个用于列表识别的图标，不表达难度或评价 |
| `file` | 指向存在且可加载的 Markdown 文件 |
| `words` | 课程反复使用的完整核心单词，不收录无法查询的词根词缀 |

### 3. 多章节目标模型

未来界面支持一门课程包含多个章节时，增加稳定的章节标识、标题、文件、深度和核心路径标记。扩展清单字段前必须同步修改 TypeScript 接口、加载逻辑、课程列表、进度记录和移动端展示，不在 JSON 中先行堆积未使用数据。

## 八、编写与验收流程

### 1. 编写前

- 确认课程中心问题和章节在 `_curriculum.md` 中的归属；
- 明确阅读场景、术语范围和领域知识边界；
- 收集真实、可核验的例句或技术语境；
- 确定需要的术语对比、常见搭配、例句和回看要点；
- 涉及易变化技术事实时查验官方资料并记录查验日期。

### 2. 内容验收

- [ ] 一级标题与课程清单标题一致；
- [ ] 课程导读说明中心问题、知识地图和边界；
- [ ] 每章说明术语或语言形式会在哪里出现；
- [ ] 核心解释先于术语细节和例外；
- [ ] 关键术语具有自然语境、搭配和相邻概念对比；
- [ ] 领域概念只讲到足以读懂英文材料的程度；
- [ ] 没有练习、综合任务或折叠答案区；
- [ ] 规则没有在多个表格和段落机械重复；
- [ ] 深层内容仍然服务于英语理解，而不是转为学科教程；
- [ ] 不把固定音素数、时态数、词根数等教学分类写成唯一事实。

### 3. 文风验收

- [ ] 标题没有宣传性词汇、数字噱头或无意义的“英语”字样；
- [ ] 没有用口诀、比喻或拟人化替代核心解释；
- [ ] 术语首次出现时有简明解释，前后命名一致；
- [ ] 示例自然，中文解释不是逐词硬译；
- [ ] 技术内容用任务、系统关系或生命周期组织英文术语，而不是教授系统实现。

### 4. 排版与交互验收

- [ ] 没有 ASCII 字符画；
- [ ] Mermaid 类型与知识关系匹配，并在实际页面成功渲染；
- [ ] 只有需要横向对齐比较的内容使用表格；
- [ ] 没有把单向枚举或逐项解释包装成表格；
- [ ] 同章多表已经完成合并或替代审查；
- [ ] 表格列数正确、宽度克制，窄屏下可读；
- [ ] 单词点击后朗读并打开词典，句子只朗读；
- [ ] 词根词缀没有词典或朗读交互，也没有按钮式悬停反馈；
- [ ] `form` 只改变样式，没有改变内容类型对应的点击行为；
- [ ] 单词保持整体，句子和说明文字自然换行；
- [ ] 命令、代码和日志使用 fenced code block；
- [ ] 高亮颜色低饱和，不使用警告红表达普通不规则形式；
- [ ] 可点击标签支持键盘操作和清晰焦点；
- [ ] 右侧目录正确显示标题并可定位；
- [ ] 桌面端和移动端均完成视觉检查。

### 5. 文件与回归验收

- [ ] `_*.md` 没有进入课程清单或课程正文批量校验；
- [ ] JSON 可解析，`id`、顺序、文件名前缀符合当前实现；
- [ ] `slug` 唯一，`file` 指向真实文件；

- [ ] 路径、编号或 `slug` 变化已经确认进度兼容策略；
- [ ] 项目构建及相关测试通过；
- [ ] 本次修改没有顺带改变无关课程内容。

## 九、维护原则

- 本文件是课程与章节写作、排版、标签、交互和验收的唯一规范依据；
- 课程分类、目录和主题边界只在 `_curriculum.md` 维护；
- 修改标签协议、文件协议或必备结构时提升规范版本；
- 修改单个事实、示例或措辞不需要提升规范版本；
- 规范描述目标协议；实现暂未支持的能力必须在发布新内容前完成并验证；
- 课程质量以学习者能否建立理解、完成任务并继续深入判断，不以篇幅、表格数量、图表数量或术语数量判断。
